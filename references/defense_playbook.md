# 防御 Playbook（16 类标准攻击怎么接）

## 这份文件解决什么

`playbooks.md` 回答「审稿人会怎么打」，本文件回答「**打过来怎么接**」。

语料里有一个字段一直没被用起来：每条意见的 `request`（审稿人要求你做什么）。它是 48,422 条意见里最接近「标准答案」的部分——审稿人自己写下了他认为合格的补救。本文件的「典型诉求」全部直接摘自该字段，带论文 id 可回溯。

**口径**：本文件只有「典型诉求」是语料证据（带 id，可回溯 `data/comments_all.jsonl`）；「标准返修」「防不住就该改的」「档位」均为评审经验判断，**不是语料统计**，引用时不得混为一谈。

## 三档应对原则

命中弱点后，只有三种诚实的选择，按优先级：

| 档 | 适用 | 做法 |
|---|---|---|
| **A 补** | 数据有、分析没做；或做一次几小时到几天 | 直接补做，写进正文，**不要写进 response 辩解** |
| **B 收窄** | 补不了，但结论可以缩小到数据支持的范围内 | 改标题/摘要/结论措辞，把 claim 降到证据线以下 |
| **C 承认** | 补不了也收不窄（设计层面的硬约束） | 在 Limitations 里明确写出，说明它限制了哪条结论，不限制哪条 |

**最常见的错误是 D 档：用文字辩解假装 A 档。** 审稿人几乎总能看出来，而且会因此追加一轮。三档之外没有第四档。

## 性价比排序（时间有限时先做这些）

| 序 | 动作 | 覆盖类别 | 成本 |
|---:|---|---|---|
| 1 | 摘要/标题逐句标注支撑它的结果，超出的降级措辞 | framing, interpretation, novelty, generality | 2h |
| 2 | 补一张「分析 → 数据 → 软件 → 参数」对照表进补充材料 | methods_reporting, stats | 半天 |
| 3 | 随机效应结构重新论证（列出所有非独立来源，逐一对应到随机项） | stats（全库第一攻击点） | 1d |
| 4 | 每个主结论换一种合理方法/参数重跑一次 | robustness | 1–3d |
| 5 | 把每个对照「隔离了什么混淆」写成一张表 | design, causality | 2h |
| 6 | 伦理/数据/贡献声明逐项核对期刊 checklist | other, data_code | 1h |
| 7 | 所有图独立可读性检查（不看正文能否懂） | figures, presentation | 3h |

前两条做完，通常能消掉一半以上的 major。

## 证据层：作者实际动作分布

下面每一类末尾都有一行 `作者实际动作`。它来自 **13,145 组** NEE「审稿意见 → 作者回复」配对（460 篇 NEE 论文，其中 7,613 对能对应到类别标签）。

**口径与限制（读之前必须知道）**：

- `n` 是该类别的配对总数；`可分类` 是其中能被规则判定动作方向的比例（38–63%）
- 百分比只在**可分类**的部分里计算，不是全样本比例
- 这是**动作分布，不是成功率**。我们没有可靠的「第二轮认可」数据，**不能**据此推断哪种做法更有效
- 动作定义：**A 补**（补数据/分析/实验）· **B 收窄**（改措辞/删减/降调）· **C 承认**（承认局限但未补）· **D 硬顶**（不同意、拒绝改）
- 语料只覆盖 Ecology Letters 与 Nature Ecology & Evolution 的首轮评审；跨学科使用请打折

## 1. framing — 立论与叙事

**他们真正要的**：摘要里每个 claim，在引言里都有铺垫；引言的缺口自然推出你的问题，中间不跳步。
**标准返修**：① 给摘要每句话标一个「支撑它的结果编号」，标不出的删或降级；② 引言改成「已知 → 矛盾/缺口 → 本问题」三段式，砍掉纯文献罗列；③ 补引被漏的关键前作（审稿人常就是被漏的那位）。
**防不住就该改的**：如果整个选题的动机都建立在「没人做过」上，改文字救不了——这是第 0 关问题。
**作者实际动作**（NEE n=761，可分类 53%）：A 补 50% · B 收窄 44% · C 承认 3% · D 硬顶 3%
**典型诉求**："Justify the five functions early, in paragraph three (lines 43-53)." — `10.1038/s41559-022-01710-5`
**衔接**：漏引前作 → 同时触发 §9 novelty。

## 2. stats — 统计分析

**他们真正要的**：随机效应覆盖全部非独立结构；模型选择有依据；样本量撑得起检验。
**标准返修**：① 列一张「非独立来源 → 随机项」对照表，漏一个补一个；② 报 AIC/BIC 和模型比较，不要只报最终模型；③ 检查有没有「先标准化再当协变量」的循环；④ 报告检验力或效应量，别只报 p。
**防不住就该改的**：样本量/重复数不足导致的检验力问题——加协变量、换模型都是化妆，只能降级结论。
**作者实际动作**（NEE n=566，可分类 57%）：A 补 58% · B 收窄 36% · C 承认 2% · D 硬顶 3%
**典型诉求**："Report model comparisons and AICs and justify the random-effect structure." — `10.1038/s41559-022-01686-2`
**注意**：NEE 严决定组 70.3% 命中此类，这是全库最高危的单点。

## 3. interpretation — 解读过度

**他们真正要的**：结论强度 = 证据强度；与假设相反的结果被正面处理，而不是绕过。
**标准返修**：① 全文搜 `drive / cause / determine / demonstrate`，逐个换成数据能支撑的动词（associate / coincide with / are consistent with）；② 每个机制性结论旁注明它依赖哪个假设；③ 与假设矛盾的结果单开一段讨论，给出替代解释。
**防不住就该改的**：如果是用 proxy（遥感、实验室指标、模式生物）回答系统层面的问题，收窄不到「机制」就只能收窄到「关联」。
**作者实际动作**（NEE n=707，可分类 60%）：A 补 33% · B 收窄 59% · C 承认 3% · D 硬顶 5%
**典型诉求**："Soften the remarkable-convergence statement at line 303." — `10.1038/s41559-022-01692-4`

## 4. methods_reporting — 方法报告不全

**他们真正要的**：没做过这个实验的人，只读方法节能复现每一个数字。
**标准返修**：① 对照表（分析 → 数据 → 软件及版本 → 关键参数）；② 正文方法节保留「复现主结果的最小集」，其余进补充材料但要有索引；③ 每个补充分析标一句「支撑正文哪条结论」。
**防不住就该改的**：关键步骤当时没记录、没做对照——补文字没用，只能补做实验或删掉依赖它的结论。
**作者实际动作**（NEE n=1032，可分类 52%）：A 补 62% · B 收窄 35% · C 承认 2% · D 硬顶 2%
**典型诉求**："Report scan resolutions, topN method, spray voltage, column and gradient details." — `10.1038/s41559-022-01701-6`

## 5. causality — 因果与替代解释

**他们真正要的**：你列出了所有合理替代解释，并说明数据为什么排除了它——或者诚实承认排除不了。
**标准返修**：① 一张「结果 → 可能成因 → 我的数据能否区分」表；② 每个对照写清隔离了什么机制；③ 排不掉的写进 Limitations，并说明它影响哪条结论。
**防不住就该改的**：处理混淆（两个因素同时变）——只能加处理组或降级为相关研究，文字层面无解。
**作者实际动作**（NEE n=442，可分类 58%）：A 补 48% · B 收窄 34% · C 承认 5% · D 硬顶 12%
**典型诉求**："Test piecemeal addition of different bacteria before claiming a diversity effect." / "Acknowledge that the demonstration does not establish a diversity effect." — `10.1038/s41559-022-01686-2`

## 6. definitions — 概念与术语

**他们真正要的**：核心概念有明确定义、全文一致、不与领域标准定义冲突。
**标准返修**：① 建一张术语表（术语 → 定义 → 首次出现位置 → 操作化指标）；② 近义概念（plasticity/evolution、heterogeneity/stochasticity）明确区分并各给一例；③ 自创术语必须在摘要前就有定义。
**防不住就该改的**：概念本身没有可操作化定义（说不清怎么测）——这是问题本身没想清楚，回到第一关。
**作者实际动作**（NEE n=457，可分类 59%）：A 补 33% · B 收窄 62% · C 承认 2% · D 硬顶 3%
**典型诉求**："Define what level of dairy consumption counts as dairying." — `10.1038/s41559-022-01701-6`

## 7. robustness — 稳健性

**他们真正要的**：主结论至少在一种替代设定下仍然成立。
**标准返修**：① 换一种合理方法/参数/子集重跑主分析，结果放补充材料；② 敏感性分析（去掉最 influential 的点/组）；③ 分组后模式是否还在。
**防不住就该改的**：结论只在唯一设定下成立且无法复现——那就是不稳健，直接降级。
**作者实际动作**（NEE n=329，可分类 63%）：A 补 68% · B 收窄 22% · C 承认 3% · D 硬顶 8%
**典型诉求**："Test whether the Fig. 2E correlation holds without S. rigidula." — `10.1038/s41559-022-01692-4`

## 8. data — 数据本身

**他们真正要的**：每个数据源的采样设计、分辨率、偏差都写得出来；跨源合并论证过可比性。
**标准返修**：① 数据溯源表（来源 → 采样设计 → 分辨率 → 已知偏差）；② 样本数全文对齐（方法、图注、补充表三处必须一致）；③ 合并数据的可比性单独一段论证。
**防不住就该改的**：数据本身代表性不足（如单一群体、非代表性群落）——只能收窄外推范围，并在 Limitations 明写。
**作者实际动作**（NEE n=445，可分类 57%）：A 补 55% · B 收窄 32% · C 承认 6% · D 硬顶 8%
**典型诉求**："Discuss the consequences of using a non-representative seeding community." — `10.1038/s41559-022-01686-2`

## 9. novelty — 新颖性

**他们真正要的**：一句话说清「相对最近的 X，本文新在 Y」，且这个 Y 对该刊读者重要。
**标准返修**：① 引言末尾加一段「与最接近的三篇工作的差异」；② 明确区分「新系统 / 新方法 / 新结论 / 新框架」，别混着说；③ 删掉撑不住的「首次」。
**防不住就该改的**：如果差异真的只是「换了个系统」，这是第 0 关问题，改文字无效。
**作者实际动作**（NEE n=162，可分类 46%）：A 补 31% · B 收窄 55% · C 承认 8% · D 硬顶 7%
**典型诉求**："Articulate the novel contribution beyond prior individualisation studies." — `10.1038/s41559-022-01773-4`
**注意**：综述类 41.3%、方法类 42.9% 被挑得最狠。

## 10. presentation — 结构与表达

**他们真正要的**：每节只干一件事；验证性结果在正文；非本领域读者读得懂首段。
**标准返修**：① 结果章节每段开头写「假设 + 检验」，一段一结论；② 把埋在补充材料里的关键验证挪回正文；③ 砍重复叙述（结果里说过的，讨论不要再复述数据）。
**防不住就该改的**：这一类的 major 只有 27.1%，但提及率 94.6%——**先修别的，这个最后做**，除非它已经掩盖了你的关键结果。
**作者实际动作**（NEE n=1259，可分类 55%）：A 补 22% · B 收窄 75% · C 承认 1% · D 硬顶 2%
**典型诉求**："Rewrite parts of the Results, stating the hypothesis and test at the start of each paragraph." — `10.1038/s41559-022-01795-y`

## 11. design — 实验设计

**他们真正要的**：每个对照隔离一个混淆；重复数撑得起要检测的效应；设计能唯一支撑想要的推断。
**标准返修**：① 画「处理 × 重复 × 测量」矩阵表；② 每个对照写一句「它排除了什么」；③ 补不了重复就报效应量和检验力，把结论降级为「初步证据」。
**防不住就该改的**：n=1、处理混淆、缺关键对照——这些补不了，只能承认并降级，或重做。
**作者实际动作**（NEE n=199，可分类 57%）：A 补 60% · B 收窄 21% · C 承认 6% · D 硬顶 12%
**典型诉求**："Clarify the unit of replication and address the pseudoreplication concern." — `10.1038/s41559-022-01686-2`
**注意**：experimental 类 50.2% 因设计被列 major，是做实验的稿子的第二大类。

## 12. generality — 普适性外推

**他们真正要的**：claim 的范围 = 数据的范围。
**标准返修**：① 标题和摘要里的 `global / universal / general` 逐个降级或加限定；② 明确写出「本结论适用于 X 条件，超出此范围未验证」；③ 有条件就加系统验证，没条件就收窄。
**防不住就该改的**：两个点位参数化就声称普适——收窄措辞是唯一出路。
**作者实际动作**（NEE n=135，可分类 60%）：A 补 49% · B 收窄 40% · C 承认 2% · D 硬顶 9%
**典型诉求**："Vary community composition to test the generality of the conclusions." — `10.1038/s41559-022-01768-1`

## 13. model_theory — 模型与理论

**他们真正要的**：假设逐条给出依据 + 违反时的后果；结论对模型结构选择不敏感；比较的量在数学上可比。
**标准返修**：① 假设清单表（假设 → 依据 → 若违反，哪条结论失效）；② 换模型结构重跑关键结果；③ 检查所有跨条件比较的量是否同量纲/同周期。
**防不住就该改的**：模型核心结构假设与生态现实明显不符（全连接 vs 稀疏网络）——只能改模型或把结论限定在模型内部。
**作者实际动作**（NEE n=106，可分类 51%）：A 补 43% · B 收窄 33% · C 承认 7% · D 硬顶 17%
**典型诉求**："Contrast a selective predation model with theirs or explain why selectivity increases with virulence." — `10.1038/s41559-022-01772-5`
**注意**：theory_model 类 72.5% 栽在此类，是全库最集中的单一命中。

## 14. figures — 图表

**他们真正要的**：每张图独立可读；色盲安全；最重要的结果在正文图里。
**标准返修**：① 只读图注能否知道画的是什么（让同事试）；② 换色盲友好配色；③ 补充表不是软件原始输出，要有表头和单位。
**防不住就该改的**：无——这一类纯技术性，改就是了，别辩解。
**作者实际动作**（NEE n=876，可分类 56%）：A 补 41% · B 收窄 58% · C 承认 1% · D 硬顶 1%
**典型诉求**："Plot the underlying data rather than only summary statistics." — `10.1038/s41559-022-01768-1`

## 15. data_code — 数据与代码可得性

**他们真正要的**：别人能跑通你的代码，复现出你的数字。
**标准返修**：① 打包成 renv / docker，写清运行顺序；② 数据文件名和代码里的变量名对齐；③ 提供 accession number 和完整中间结果（不只最终汇总）。
**防不住就该改的**：原始数据受第三方限制不能公开——写清限制原因和申请途径，别写 "available upon request"。
**作者实际动作**（NEE n=115，可分类 38%）：A 补 64% · B 收窄 27% · C 承认 0% · D 硬顶 9%
**典型诉求**："Package the code reproducibly (renv or docker) and align data and code names." — `10.1038/s41559-022-01820-0`
**注意**：major 只有 7.8%，但真有审稿人会下载代码跑一遍。成本低、风险高，值得提前做。

## 16. other — 伦理/政策/杂项

**他们真正要的**：合规信息完整可查。
**标准返修**：① 伦理批号 + 批准机构全称 + 知情同意方式 + 数据保护措施；② 作者贡献按 CRediT 逐项写；③ 政策建议必须有数据支撑，否则删或降级为「探讨」。
**防不住就该改的**：伦理审批缺失——无法补救，直接撤稿重走流程。
**典型诉求**："Provide the full ethical review board name and the measures for consent, confidentiality and data protection." — `10.1038/s41559-023-02037-5`
**注意**：major 仅 1.5%，但一旦命中可直接拒稿，是全库唯一「低频高杀伤」类别。

## 写 response 的三条硬规矩

1. **A 档动作不要写进 response 当辩解**。补做了就直接说「已补，见 Fig. Sx」——审稿人要的是结果，不是理由。
2. **C 档必须点名限制哪条结论**。写「这是一个 limitation」是敷衍；写「该限制不影响结论 1 和 3，但使结论 2 只能作为初步证据」才是回答。
3. **不要一条条反驳全部意见**。挑 major 逐条正面回应，minor 可以合并成一段「我们已按建议修改了 X、Y、Z」。逐条硬顶 minor 会消耗审稿人耐心，反而抬高 major 的火力。

## 与输出的衔接

第三步输出弱点清单时，每条命中后加一行：

```
- 应对档位：A 补 / B 收窄 / C 承认
- 最高性价比动作：…（见 defense_playbook §n）
- 若不做，风险：…（对应 stats_overview 的 major%）
```

这一行决定了用户拿到清单后**能不能动手**。只给问题不给档位，等于把工作又推回给他。
